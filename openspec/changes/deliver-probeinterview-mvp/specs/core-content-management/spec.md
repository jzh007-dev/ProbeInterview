# Spec Delta

## Purpose

定义平台核心知识和核心题目的版本化导入、稳定知识点标识、发布版本及选题用途，使公共核心考察和题库兜底具有受控且可追溯的内容来源。

## ADDED Requirements

### Requirement: 平台核心内容通过版本化文件导入
系统 SHALL 支持管理者通过 XMind 和 Markdown 文件或一次性导入工具补充平台核心内容，并 MUST NOT 要求 MVP 提供在线管理员 CMS。

#### Scenario: 管理者导入平台内容
- **WHEN** 管理者提交符合约定的 XMind 知识层级和 Markdown 知识或题目文件
- **THEN** 系统解析为候选内容版本并提供导入结果

#### Scenario: 导入文件格式不受支持
- **WHEN** 管理者提交 XMind 和 Markdown 以外的文件作为平台核心内容
- **THEN** 系统拒绝导入并指出支持的文件格式

### Requirement: 导入内容必须校验后原子发布
系统 SHALL 在发布前校验知识层级、稳定来源键、题目字段、知识点绑定、能力标签和适用年限，并 SHALL 保证失败的导入不会产生部分发布。

#### Scenario: 候选内容校验通过
- **WHEN** 候选导入不存在阻断错误且管理者确认发布
- **THEN** 系统将全部候选内容作为一个新版本原子发布

#### Scenario: 候选内容存在阻断错误
- **WHEN** 候选导入存在来源键冲突、悬空知识点引用或必填评分信息缺失
- **THEN** 系统输出可定位的错误且 MUST NOT 发布该候选版本的任何内容

### Requirement: XMind 建立知识层级和稳定知识点 ID
系统 SHALL 使用 XMind 节点建立能力与知识点层级，并 SHALL 通过持久化来源键保持知识点 ID 在后续版本中稳定。

#### Scenario: 知识点改名或移动
- **WHEN** 后续导入保留同一来源键但修改知识点名称或层级位置
- **THEN** 系统保留原稳定知识点 ID 和既有面试、证据及复盘关联

#### Scenario: 来源键缺失或冲突
- **WHEN** 系统无法唯一确定一个节点应沿用的稳定知识点 ID
- **THEN** 系统将其标记为阻断错误并要求人工处理，MUST NOT 根据名称相似度自动合并

### Requirement: 核心题目具有可验证的评分信息
平台核心题目 SHALL 包含题目正文、关联能力、稳定知识点 ID、5 至 10 年适用范围、难度、参考答案或评分要点以及可用状态。

#### Scenario: 题目信息完整
- **WHEN** 导入题目包含全部必填字段且知识点 ID 有效
- **THEN** 系统将其纳入候选内容版本并允许发布后参与选题

#### Scenario: 题目缺少评分或绑定信息
- **WHEN** 导入题目缺少能力、知识点 ID、适用年限或评分要点
- **THEN** 系统将其标记为不可发布且 MUST NOT 作为新面试候选题

### Requirement: 平台核心内容具有不可变发布版本
系统 SHALL 为每次成功发布的平台核心内容建立不可变版本，并 SHALL 保留历史版本供既有面试配置快照引用。

#### Scenario: 新面试引用当前内容版本
- **WHEN** 系统开始一场模拟面试
- **THEN** 系统在配置快照中记录本场使用的平台核心内容版本

#### Scenario: 发布新内容版本
- **WHEN** 新平台内容版本成为当前版本
- **THEN** 新面试使用新版本且历史面试仍可解析其原始内容版本

#### Scenario: 新版本停用旧题目
- **WHEN** 某道核心题目在新版本中被设为不可用
- **THEN** 新面试不再选择该题目且历史面试仍保留原题目快照

### Requirement: 平台核心题库承担公共核心和兜底选题
系统 SHALL 从当前内容版本中选择适配工作年限、语言和能力范围的公共核心题目，并可在私人题库不足时补足候选题。

#### Scenario: 用户私人题库不足
- **WHEN** 用户私人题库无法提供足够的合格候选题
- **THEN** 系统使用平台核心题库或受控生成候选补足，并记录最终实际题目来源

#### Scenario: 核心题目仍然不足
- **WHEN** 平台核心题库也无法满足计划覆盖
- **THEN** 系统记录覆盖不足并 MUST NOT 通过重复或不相关题目伪造目标比例
