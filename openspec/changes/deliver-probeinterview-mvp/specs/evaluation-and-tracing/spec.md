# Spec Delta

## Purpose

建立默认私有、可人工评估且为未来证据图和重放演进保留核心数据的最小面试 Trace，并分离候选人短板与系统失败。

## ADDED Requirements

### Requirement: 系统记录六类最小面试 Trace
系统 SHALL 至少记录面试创建、题目展示、转录确认、过程评分、最终评分和复盘创建六类关键事件，但 MVP MUST NOT 依赖完整事件溯源恢复全部业务状态。

#### Scenario: 一场面试完成完整闭环
- **WHEN** 用户完成面试、查看最终评分并创建复盘
- **THEN** 系统能够定位该面试对应的六类关键事件及其发生顺序

#### Scenario: 最终评分调整过程评分
- **WHEN** 完整对话校准得到与过程评分不同的最终结论
- **THEN** 系统保留原过程评分事件、最终评分事件、各自证据引用和版本信息

### Requirement: Trace 事件具有稳定关联和版本引用
每条 Trace 事件 SHALL 包含稳定事件 ID、时间戳、事件类型、关联面试与实体 ID、correlation ID、证据引用及适用的模型、Prompt、评分规则和内容版本。

#### Scenario: 团队排查一条评分结果
- **WHEN** 团队从最终评分事件开始追查
- **THEN** 系统能够定位关联问题、确认回答、证据片段、知识点及产生结果时使用的版本

#### Scenario: 关联实体不存在
- **WHEN** 系统尝试写入引用不存在或不属于该面试的实体 ID
- **THEN** 系统拒绝该事件并记录内部数据完整性失败

### Requirement: 面试保存不可变输入和版本快照
每场面试 SHALL 保存配置、简历解析结果、JD、公司场景、平台内容版本、私人题库版本、模型、Prompt、评分规则和评估配置版本。

#### Scenario: 后续发布新评分规则
- **WHEN** 新评分规则生效
- **THEN** 历史面试仍能识别其原始规则版本且最终分数不被自动重算

#### Scenario: 当前简历或平台内容更新
- **WHEN** 用户替换当前简历或系统发布新平台内容版本
- **THEN** 历史面试继续引用创建时保存的输入和版本快照

### Requirement: 用户面试默认进入私人参考样本
系统 SHALL 将已完成面试的确认文本、配置、评分、证据和短板保存在该用户的私人面试参考样本中，并 MUST NOT 包含已删除的原始录音。

#### Scenario: 用户完成面试
- **WHEN** 最终报告生成
- **THEN** 系统创建仅 owner 可访问的私人参考样本

#### Scenario: 其他身份请求参考样本
- **WHEN** 其他身份请求访问不属于自己的私人面试参考样本
- **THEN** 系统拒绝访问且不泄露样本是否存在

### Requirement: 候选人失败和系统失败分别记录
系统 SHALL 将回答证据暴露的知识与能力短板记录为用户可见失败，将提问、解析、OCR、转写、模型调用、结构化输出和评分链路错误记录为内部系统失败。

#### Scenario: 用户回答缺少评测方法
- **WHEN** 确认回答证据显示候选人未能定义有效评测
- **THEN** 系统记录候选人“评测不足”短板并允许用户选择加入复盘

#### Scenario: 转写服务错误导致无可靠文本
- **WHEN** 用户录音有效但转写服务未产生可确认文本
- **THEN** 系统记录系统失败且 MUST NOT 记录为候选人短板

### Requirement: 线上面试只运行一个 Agent
系统 SHALL 在真实线上面试中只运行一个面试 Agent 完成提问、过程评分和完整对话最终校准；第二评估 Agent MUST NOT 参与线上请求或用户最终分数生成。

#### Scenario: 线上面试完成评分
- **WHEN** 一场真实用户面试结束
- **THEN** 最终分数由本场面试 Agent 基于完整确认转录生成

#### Scenario: 团队运行第二评估 Agent
- **WHEN** 团队需要比较不同评分判断
- **THEN** 第二评估 Agent 仅在本地离线评估运行中处理固定评估样本

### Requirement: 固定评估集由人工锚点和审核变体组成
系统评估集 SHALL 包含人工定义的标准样本、LLM 生成的回答变体及其人工审核状态，并 SHALL 覆盖 5 至 10 年基线以及薄弱、达标和优秀回答。

#### Scenario: LLM 生成新变体
- **WHEN** LLM 为标准样本生成新的回答变体
- **THEN** 该变体在人工确认标签、证据锚点和期望结果前 MUST NOT 进入固定评估集

#### Scenario: 评估样本缺少人工期望
- **WHEN** 样本没有人工确认的分数区间或短板标签
- **THEN** 离线评估运行器拒绝将其作为固定基准样本

### Requirement: MVP 支持本地手动评估和人工比较
系统 SHALL 支持管理者手动运行固定评估集，并 SHALL 输出当前评分链路与离线第二 Agent 的五维分差、等级变化、短板标签、证据引用、失败分布、延迟和成本供人工比较。

#### Scenario: 管理者运行固定评估集
- **WHEN** 管理者手动启动指定版本的离线评估
- **THEN** 系统生成带模型、Prompt、评分规则和评估集版本的结构化比较结果

#### Scenario: 评估结果发生明显变化
- **WHEN** 候选版本与当前版本的分数、等级或短板标签存在差异
- **THEN** 系统在比较结果中披露差异，但 MVP 不自动计算持续漂移趋势或自动阻止发布

### Requirement: 系统不得根据 Trace 自动发布改进
MVP MUST NOT 根据系统失败 Trace 或评估结果自动修改并发布线上 Prompt、评分规则、题目或模型配置。

#### Scenario: 系统发现重复评分失败
- **WHEN** 多个 Trace 显示相同类型的评分链路问题
- **THEN** 系统保留失败记录供人工分析，但不自动修改线上行为

#### Scenario: 管理者准备采用候选配置
- **WHEN** 管理者根据手动评估决定使用新的模型、Prompt 或评分规则
- **THEN** 新配置必须以新版本显式发布且历史面试保持原版本

### Requirement: 私人内容不自动进入共享评估集
系统 MUST NOT 自动将用户简历、JD、完整回答、私人资料或私人题库用于共享评估集或模型训练；内部系统指标只能使用经人工选择且符合隐私要求的样本或不含原始私人内容的聚合信息。

#### Scenario: 真实用户面试产生系统失败
- **WHEN** 真实面试产生系统失败 Trace
- **THEN** 系统可以记录错误类型和版本信息，但 MUST NOT 将完整私人内容自动复制到共享评估集

### Requirement: MVP 保存未来重放所需核心数据但不提供重放产品
系统 SHALL 保存足以在未来定位输入快照、关键事件顺序、证据引用、稳定实体关系和版本的数据，但 MVP MUST NOT 要求提供重放界面、评估管理后台、自动漂移统计平台、发布门禁平台或完整证据图。

#### Scenario: 团队检查演进数据完整性
- **WHEN** 一场面试完成
- **THEN** 系统能够定位其输入快照、六类关键事件、证据引用、模型与规则版本以及最终输出

#### Scenario: 用户尝试打开重放或评估管理页面
- **WHEN** 用户在 MVP 中查找重放、评估管理或漂移监控入口
- **THEN** 系统不提供这些延期能力的用户界面
