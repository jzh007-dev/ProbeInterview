# Spec Delta

## Purpose

将面试报告中的证据化短板转化为由用户确认、按面试分组、可学习和可归档的复盘流程，并通过稳定知识点 ID 连接个人知识卡片与长期训练记录。

## ADDED Requirements

### Requirement: 用户确认短板后才创建复盘
系统 SHALL 在面试报告中展示候选短板，并 SHALL 仅将用户明确选择和确认的知识点加入待复盘。

#### Scenario: 用户选择部分短板
- **WHEN** 用户从候选短板中选择一个或多个知识点并确认
- **THEN** 系统为本场面试创建包含所选知识点的待复盘批次

#### Scenario: 用户不选择短板
- **WHEN** 用户离开报告且未确认任何知识点
- **THEN** 系统不创建待复盘批次

### Requirement: 低置信度知识点映射需要用户确认
当候选短板无法高置信度映射到有效平台知识点 ID 或私人知识点 ID 时，系统 SHALL 展示建议映射供用户确认，MUST NOT 自动建立低置信度关联。

#### Scenario: 用户确认建议知识点
- **WHEN** 用户确认系统提供的低置信度知识点映射
- **THEN** 系统使用该知识点 ID 创建复盘项

#### Scenario: 用户拒绝建议知识点
- **WHEN** 用户拒绝全部建议映射但仍选择加入复盘
- **THEN** 系统创建标记为 AI 推断的私人临时知识点 ID 并用于本次复盘

### Requirement: 每场面试最多创建一个复盘批次
每场面试 SHALL 最多关联一个待复盘批次，该批次 SHALL 包含用户从本场面试选择的多个知识点。

#### Scenario: 用户再次从同一报告添加短板
- **WHEN** 本场面试已存在待复盘批次且用户补充选择其他短板
- **THEN** 系统将新项目加入同一批次而非创建第二个批次

#### Scenario: 用户重复提交同一短板
- **WHEN** 用户在同一面试批次中再次确认相同知识点 ID
- **THEN** 系统保持一个复盘项且 MUST NOT 创建确定性重复

### Requirement: 复盘页置顶最近面试并列出全部待复盘批次
复盘页 SHALL 展示最近一次面试复盘摘要，并 SHALL 在其下按时间倒序展示全部未归档批次及完成进度。

#### Scenario: 用户存在多个待复盘批次
- **WHEN** 用户打开复盘页
- **THEN** 最近一次面试置顶且所有未完成批次均可访问

#### Scenario: 用户没有待复盘批次
- **WHEN** 用户打开复盘页且不存在未归档批次
- **THEN** 系统展示空状态且不创建虚拟复盘内容

### Requirement: 用户手动完成知识点复盘
系统 SHALL 允许用户逐个将复盘知识点标记为完成，MUST NOT 强制要求验证题或自动判断掌握程度。

#### Scenario: 用户完成一个知识点
- **WHEN** 用户点击某个复盘项的完成操作
- **THEN** 系统记录完成时间并更新批次进度

#### Scenario: 批次所有知识点完成
- **WHEN** 批次中的全部复盘项均已完成
- **THEN** 系统自动将该批次归档

### Requirement: 重复短板创建新的时间化复盘项
同一知识点在新的面试中再次被用户加入复盘时，系统 SHALL 创建属于新面试批次的新复盘项，并 SHALL 增加知识卡片上的累计复盘次数。

#### Scenario: 已完成知识点再次成为短板
- **WHEN** 用户在后续面试报告中再次选择同一知识点 ID
- **THEN** 系统创建新的复盘项并保留此前所有复盘历史

### Requirement: 复盘按稳定知识点 ID 优先使用已有卡片
系统 SHALL 优先按平台稳定知识点 ID 或私人临时知识点 ID 关联用户已有知识卡片；没有关联卡片时 SHALL 由 LLM 生成知识解释、遗漏要点和改进回答思路。

#### Scenario: 知识点 ID 已关联用户卡片
- **WHEN** 复盘知识点 ID 已存在对应的用户知识卡片
- **THEN** 系统在复盘详情中优先展示该卡片

#### Scenario: 知识点 ID 没有关联卡片
- **WHEN** 复盘知识点 ID 没有对应的用户知识卡片
- **THEN** 系统生成 AI 知识卡片、标记其来源并关联本次复盘

#### Scenario: 存在文本相似但 ID 不同的卡片
- **WHEN** 用户已有文本相似但知识点 ID 不同的卡片
- **THEN** 系统 MUST NOT 根据语义相似度自动合并或替换卡片

### Requirement: 通用知识与个人失败证据分离
知识卡片 SHALL 保存可重复学习的通用内容；本次问题、个人回答、遗漏点、评分和失败标签 SHALL 仅保存在对应复盘与面试记录中。

#### Scenario: 用户查看知识卡片
- **WHEN** 用户从首页打开一个与复盘关联的知识卡片
- **THEN** 卡片展示通用知识和复盘次数，但不混入某次面试的完整个人回答

#### Scenario: 用户查看复盘详情
- **WHEN** 用户从复盘批次打开该知识点
- **THEN** 系统展示本次面试证据以及关联的通用知识卡片

### Requirement: 知识卡片显示复盘时间线状态
系统 SHALL 在知识卡片上展示累计进入复盘次数、是否存在当前待复盘项以及最近复盘时间。

#### Scenario: 第三次进入复盘
- **WHEN** 一个知识点第三次被用户确认加入复盘
- **THEN** 对应知识卡片显示“第 3 次进入复盘”和当前待复盘状态

#### Scenario: 当前复盘批次已归档
- **WHEN** 知识点不再存在未完成复盘项
- **THEN** 卡片保留累计次数和最近复盘时间，但不再显示当前待复盘状态
