# Proposal

## Why

截至 2026-09-27，项目尚未建立可交付的产品能力。该 change 将通过微信小程序面向 5～10 年经验、准备社会招聘的 AI 全栈开发者开展单用户封闭试用，建立“知识学习—模拟面试—证据评分—短板复盘”的首个完整 MVP 闭环，并从首版开始保留 ProbeGraph 后续演进所需的证据、版本和最小 Trace 数据。

## What Changes

- 提供以知识卡片流为核心的首页学习体验，并支持管理个人知识资料与个人题库；私人内容仅支持 Markdown。
- 平台核心知识库与核心题库通过版本化 XMind、Markdown 文件或一次性导入工具补充，不建设完整管理员 CMS。
- 提供 AI 应用工程专项模拟面试；综合面试以及项目深挖、全栈、系统设计、协作责任感等独立专项延后。
- 模拟前要求选择当前简历或上传新简历，并支持配置 5～10 年工作年限、可选目标公司、可选 JD、中文或英文以及 15/30/45 分钟时长。
- 简历仅支持 PDF；JD 仅支持多图上传和 OCR。用户确认 JD 解析结果后，JD 优先于经用户确认的目标公司业务场景参与出题和评分。
- 以 50%“JD 与平台公共核心共享”、30%“简历技术路线”、20%“用户个人题库”作为选题软目标，并记录实际覆盖率；不得为了满足比例加入重复或无关问题，个人题库不足时可由平台核心题库或 LLM 受控补充。
- 采用面试官文字提问、用户语音回答、自动转写的轮次式交互；每题最多录制三次，转写不可编辑，确认后立即删除原始录音。
- 使用五维固定权重进行年限相对评分：问题定义与成功指标 15%、AI 方案与模型应用 25%、路线专项能力 20%、评测与可靠性 25%、工程交付与技术取舍 15%。
- 在线面试只运行一个面试 Agent：面试中生成过程评分并据此动态追问，结束后由同一 Agent 基于完整转录校准，向用户展示最终总分、各能力分、证据覆盖和短板。第二 Agent 仅用于离线评估，不参与线上面试。
- 允许用户从候选短板中选择知识点，按每场面试创建一个待复盘批次；知识点逐个手动完成，全部完成后自动归档。
- 优先通过稳定知识点 ID 将复盘项关联到已有知识资料。平台 XMind 导入建立层级和 ID，核心题目绑定 ID，LLM 只能从受控 ID 列表中选择；低置信度映射需要用户确认，无法匹配的内容使用私人临时 ID。MVP 不实现向量语义匹配或自动卡片合并。
- 无匹配学习内容时，由 LLM 自动生成可编辑且明确标记来源的通用知识卡片。
- 建立候选人短板与系统失败两条独立记录链路。MVP Trace 只要求记录面试创建、题目展示、转录确认、过程评分、最终评分以及短板/复盘创建等关键事件。
- 为面试、问题、能力、知识点、证据片段和失败标签保留稳定标识，并保存时间戳、证据引用、不可变配置快照以及模型、Prompt、评分规则、内容和评估配置版本。
- 保留小型本地评估集和人工对比流程。自动评分漂移统计、发布门禁平台、评估集管理后台、重放界面和完整事件溯源明确延期，但其未来所需的核心数据从 MVP 开始保存。
- 用户数据默认私有并进入个人面试参考样本；单用户试用仅允许指定微信身份访问，同时保留 `user_id` 和 owner 标识以支持未来迁移。MVP 不做完整账户体系、多租户管理、简历优化、发音评价、公共数据贡献或未经评估与人工确认的自动线上改进。

## Capabilities

### New Capabilities

- `personal-learning-library`: 管理 Markdown 私人知识资料与题库、知识卡片、来源标记、学习状态及首页卡片流。
- `core-content-management`: 通过版本化 XMind、Markdown 文件或一次性导入工具维护平台核心知识、核心题目、稳定知识点 ID、评分要点和能力标签。
- `interview-configuration`: 管理 PDF 当前简历、历史面试简历快照、5～10 年工作年限、目标公司场景、JD 多图 OCR 确认、语言和时长配置。
- `ai-application-interview`: 执行 AI 应用工程专项的受控题目编排、轮次式语音回答、转写确认、动态追问和时间控制。
- `interview-assessment`: 由单一线上 Agent 生成过程评分、结束后校准、五维年限相对评分、最终报告、证据引用和候选人短板。
- `review-management`: 将用户确认的短板按面试组织为待复盘批次，并通过稳定知识点 ID 关联知识卡片、完成状态与历史归档。
- `evaluation-and-tracing`: 记录最小结构化 Trace、系统失败、版本元数据、私人参考样本，并支持小型本地评估集和人工对比。

### Modified Capabilities

无。当前项目尚无既有 capability specs。

## Impact

- 新增微信小程序端的首页学习、复盘、模拟、上传和个人中心入口，以及模拟配置、面试过程和结果报告交互。
- 新增平台内容导入流程，但不新增完整管理员 CMS、评估管理后台、发布门禁平台或重放界面。
- 新增 PDF 简历、JD 多图 OCR、Markdown 私人内容、XMind/Markdown 平台内容、知识卡片、面试、评分、复盘和最小 Trace 等持久化数据。
- 需要集成 LLM 编排、语音转写、图片文字识别、文件存储、评分校准及内部离线评估能力；线上不运行双 Agent。
- 需要落实指定微信身份访问、默认私有、原始录音即时删除、稳定 ID、历史配置快照、证据引用以及模型、Prompt、评分规则和内容版本记录。
- **演进风险**：如果 MVP 只持久化最终分数和报告，未来将无法可靠构建证据图、重放评分过程或比较版本漂移，并可能需要重建核心数据链路；因此 MVP 必须保存最小关键事件、细粒度证据引用、关系标识和版本元数据，但不要求首版实现完整证据图、自动漂移统计、完整事件溯源或可视化重放。
- 这是绿地 MVP，没有既有 API 或用户行为需要兼容，因此不包含 breaking change。
