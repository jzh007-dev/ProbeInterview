# Tasks

> 范围基线：本任务清单按 2026-09-27 已确认的 `proposal.md`、`design.md` 和已同步 specs 编排。

## 1. 工程骨架与身份入口

- [ ] 1.1 建立微信小程序、模块化后端、后台任务和离线评估运行器的工程骨架，并通过统一的构建、静态检查和测试命令验证各模块可以独立启动
- [ ] 1.2 定义 LLM、OCR、语音转写和对象存储适配器接口及测试替身，并通过契约测试验证业务模块不依赖具体供应商 SDK
- [ ] 1.3 实现微信登录换取内部 `user_id` 及单身份允许名单校验，并通过授权身份成功、非授权身份拒绝的 API 测试
- [ ] 1.4 为小程序和后端建立环境配置、密钥注入和敏感配置校验，并验证缺少必填密钥时服务拒绝启动且日志不输出密钥值

## 2. 数据模型、私有存储与最小 Trace

- [ ] 2.1 建立身份、文件、内容、配置快照、面试、回答、证据、评分、复盘、Trace、系统失败和评估运行的数据库迁移，并通过迁移往返测试及外键完整性测试
- [ ] 2.2 为所有私人实体加入稳定 ID、`owner_user_id`、时间戳和必要版本引用，并通过跨用户构造测试验证任何私人查询都不能绕过 owner 条件
- [ ] 2.3 实现私人对象存储路径、临时文件状态、幂等删除和短 TTL 兜底，并通过上传、读取授权、主动删除及重复删除测试
- [ ] 2.4 实现模型、Prompt、评分规则、平台内容、解析器和评估配置的版本注册与快照引用，并验证历史快照不会因当前版本更新而变化
- [ ] 2.5 实现六类最小 Trace 事件和候选人短板/系统失败分离的数据结构，并通过事件顺序、关联实体、correlation ID 和版本引用的单元测试

## 3. 平台核心内容导入

- [ ] 3.1 定义 XMind 知识层级和 Markdown 知识/题目文件的导入约定，并用可实际导入的示例文件验证字段、适用年限、评分要点和知识点绑定
- [ ] 3.2 实现 XMind 层级解析、Markdown 内容解析和“来源键 → 稳定知识点 ID”清单，并通过节点改名、移动后 ID 不变的回归测试
- [ ] 3.3 实现导入校验和预览报告，覆盖来源键冲突、悬空知识点引用、缺失评分信息及超出 5～10 年范围，并验证错误输入不会部分写入
- [ ] 3.4 实现不可变 `content_version` 的原子发布、当前版本切换和历史版本读取，并通过新旧面试分别引用正确版本的集成测试
- [ ] 3.5 导入首版 AI 应用工程核心知识与核心题目样本，并验证每道可选题都能解析到有效能力、知识点 ID、年限和评分要点

## 4. 私人 Markdown 知识库与首页学习

- [ ] 4.1 实现私人 Markdown 知识资料上传、解析状态、失败原因和历史记录，并通过仅接受 Markdown、错误可恢复及 owner 隔离测试
- [ ] 4.2 实现私人 Markdown 题库解析，支持缺少参考答案或评分要点时生成带“AI 推断”来源的候选信息，并通过完整题目和不完整题目用例测试
- [ ] 4.3 实现私人知识点临时 ID、知识卡片来源、用户编辑、学习状态、浏览记录和文本指纹确定性去重，并验证不执行语义自动合并
- [ ] 4.4 建立小程序“首页、复盘、模拟、上传、我的”五栏导航及中央突出模拟入口，并通过页面路由测试验证各入口可达
- [ ] 4.5 实现首页滑动知识卡片流、来源、学习状态、复盘次数和待复盘标识，并通过浏览不自动完成、手动完成才更新状态的界面测试

## 5. 简历、JD 与面试配置快照

- [ ] 5.1 实现仅 PDF 的当前简历上传、解析和替换，保留历史面试快照，并通过拒绝非 PDF、替换当前附件及历史快照不变测试
- [ ] 5.2 实现 JD 多图顺序上传、后台 OCR、失败图片重试和合并文本确认，禁止无图片的纯文本 JD，并通过图片顺序和输入限制测试
- [ ] 5.3 实现可选目标公司的业务场景生成、用户确认与通用场景降级，并验证输出不会声明掌握公司内部系统或真实题库
- [ ] 5.4 实现 5～10 年、中文/英文、15/30/45 分钟及必需 PDF 简历的配置校验，并通过边界值、缺失字段和默认 30 分钟测试
- [ ] 5.5 创建不可变面试配置快照，包含简历、JD、公司场景、语言、时长及全部版本引用，并验证用户后续修改配置不会影响历史面试
- [ ] 5.6 完成小程序“我的”简历管理和模拟配置页面，并通过一条从选择当前简历到确认配置的界面流程测试

## 6. 受控选题与面试计划

- [ ] 6.1 实现公共核心/JD、简历技术路线和私人题库三个候选池的构建与 5～10 年、语言、AI 应用工程范围过滤，并通过不同配置的候选池测试
- [ ] 6.2 实现按知识点 ID、题目 ID 和规范化文本指纹的确定性去重，并验证 JD 与公共核心重叠时只形成一次考察且保留多来源标签
- [ ] 6.3 实现 50/30/20 软目标规划、私人题库不足降级和实际覆盖率记录，并验证系统不会为凑比例选择重复或无关题目
- [ ] 6.4 实现 LLM 在受控题目/知识点 ID 列表中的结构化选择，拒绝不存在或越权 ID，并通过合法输出、幻觉 ID 和结构错误重试测试
- [ ] 6.5 实现创建面试计划和 `interview.created`、首个 `question.displayed` Trace，并通过计划快照与实际首题一致的集成测试

## 7. 语音轮次与动态面试

- [ ] 7.1 实现可恢复的面试状态机、15/30/45 分钟预算和提前结束路径，并通过合法状态迁移、非法重复请求和时间耗尽测试
- [ ] 7.2 实现小程序文字问题展示、录音、转写预览、确认提交和重新录制交互，并通过转写文本不可编辑的界面测试
- [ ] 7.3 实现每题最多三次录制、重新录制删除旧音频、确认后删除最终音频及 `transcript.confirmed` Trace，并通过删除状态和次数边界测试
- [ ] 7.4 实现语音转写后台任务、幂等回调和系统故障降级，并验证三次系统失败后可跳过或结束且不生成候选人短板
- [ ] 7.5 实现基于过程证据、覆盖缺口和剩余时间的追问/切换/结束决策，并通过回答深度不足追问、证据充分切换和时间不足结束用例测试

## 8. 单 Agent 评分与结果报告

- [ ] 8.1 定义并实现过程评分结构化 Schema，保存知识点命中、证据字符区间、深度、应用、评测、取舍和短板候选，并通过无证据结论及越界引用拒绝测试
- [ ] 8.2 在每轮确认回答后运行隐藏过程评分、写入 `assessment.processed` Trace 并驱动下一步，验证面试结束前客户端接口不返回分数
- [ ] 8.3 实现同一面试 Agent 基于完整确认转录的最终校准，禁止调用线上第二 Agent，并通过调用链测试验证每场线上面试只有一个 Agent 身份
- [ ] 8.4 实现固定五维权重、5～10 年基线、JD 维度内调整和“尚未评估”处理，并通过权重计算、年限差异、证据不足及 JD 不改变一级权重测试
- [ ] 8.5 实现唯一最终报告和 `assessment.finalized` Trace，展示总分、等级、五维能力、证据覆盖、实际题源比例、优势、短板和逐题详情，并通过 API 与页面快照测试
- [ ] 8.6 实现历史分数与报告入口，并验证更换简历、内容版本或评分规则后历史报告仍显示原始快照和原始最终分数

## 9. 短板映射与复盘闭环

- [ ] 9.1 实现受控知识点 ID 的短板映射、置信度校验和私人临时 ID 创建，并通过高置信度、低置信度待确认、无匹配及越权 ID 测试
- [ ] 9.2 实现用户在报告中选择短板后幂等创建每场最多一个复盘批次，并通过未选择不创建、重复提交不重复建批次测试
- [ ] 9.3 实现按稳定知识点 ID 关联已有卡片，无卡片时生成来源明确的通用卡片，并验证个人回答证据不会写入通用卡片正文
- [ ] 9.4 实现最近一次复盘置顶、全部待复盘批次列表、逐项手动完成和全完成自动归档，并通过多批次排序与状态迁移界面测试
- [ ] 9.5 实现重复短板的新时间化复盘项、累计复盘次数、当前待复盘状态和最近复盘时间，并通过同一知识点跨多场面试的历史测试
- [ ] 9.6 在复盘创建时写入 `review.created` Trace，并验证 Trace 能关联面试、短板证据、知识点、卡片和复盘批次
